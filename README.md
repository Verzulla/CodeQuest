# 🦉 CodeQuest

Учим Python и тестирование в игровом формате, как в Duolingo: дорожка уроков, XP и уровни,
серия дней, сердечки, дневная цель, награды за модули и темы, достижения,
работа над ошибками и статистика. Аккаунты по нику и паролю — у каждого свой прогресс.
Контент, аккаунты и прогресс хранятся в SQLite (`data/codequest.db`).

Темы (33, порядок — `content/ORDER`), по группам:

- **Python** — 24 темы: от переменных и условий до классов, декораторов, файлов, контекстных менеджеров и генераторов.
- **Инструменты** — Linux и терминал, Git, Python-проект (venv, pip, uv, ruff, pre-commit).
- **Тестирование** — pytest, Allure и отчёты, тестирование API (requests, responses, Pydantic),
  тестирование UI (Playwright), Docker, CI/CD.

Новые темы — по 12 уроков × 8 заданий; у каждого урока подробная теория, шпаргалка и «Проверь себя».

## Запуск

```bash
./run.sh
```

Открой http://127.0.0.1:8765 и зарегистрируйся. При первом запуске создастся окружение,
пустая база `data/codequest.db` (в git её нет — у каждой установки свои аккаунты и прогресс)
и загрузятся темы из `content/`.

## Аккаунты

- Регистрация — ник (3–20 символов: буквы, цифры, `_`, без учёта регистра) и пароль (от 6 символов).
  Почты и подтверждений нет, восстановления пароля тоже.
- **Первый зарегистрированный пользователь — администратор** (раздел «Контент»). Если база осталась
  от однопользовательской версии, её прогресс переходит в этот первый аккаунт.
- Администратор назначает других администраторов в «Настройках» → «🛡️ Администраторы» (по нику)
  и там же снимает права; снять их с самого себя нельзя. То же из консоли — `make-admin` / `revoke-admin`.
- Личные настройки в приложении: дневная цель, тёмная тема, сердечки, звуки и «🔒 Уроки по порядку»
  (выключи — и любой урок открывается сразу).
- Пароли — scrypt-хеш с солью; сессия — httpOnly-cookie на 5 дней, продлевается при активности.
  Смена пароля завершает сессии на других устройствах.
- Ограничения: 10 неверных паролей с одного IP за 15 минут, 5 регистраций с одного IP за час.
  Изменяющие запросы с чужого Origin отклоняются.

```bash
.venv/bin/python -m app.cli users                       # список аккаунтов
.venv/bin/python -m app.cli make-admin   <ник>          # выдать права администратора
.venv/bin/python -m app.cli revoke-admin <ник>          # забрать права
.venv/bin/python -m app.cli reset-progress <ник> --yes  # обнулить прогресс пользователя
```

За HTTPS-прокси выставь `CODEQUEST_SECURE_COOKIE=1`, чтобы cookie получила флаг `Secure`,
и передавай прокси заголовки `Host` и `X-Forwarded-For` (от них зависят проверка Origin и лимиты по IP).

## Песочница для кода учеников

Код из уроков и кнопки ▶ выполняется на сервере, поэтому он изолирован. Режим — `CODEQUEST_SANDBOX`:

| Режим | Что это | Когда |
|---|---|---|
| `docker` (по умолчанию) | одноразовый контейнер `codequest-runner` (Python 3.12 + pytest, pytest-xdist, pydantic, allure-pytest, requests, responses, httpx, jsonschema, pyyaml и pwfake — учебный Playwright без браузера, с pytest-фикстурой `page` и демо-сайтом `pwfake.demo`; `deploy/runner/Dockerfile`) на каждый запуск: без сети, read-only ФС (кроме `/tmp` 16 МБ в памяти), пользователь `nobody`, без capabilities, 256 МБ памяти, 1 CPU, до 64 процессов, 5 секунд | сервер в интернете |
| `local` | дочерний `python -I` с лимитом времени, **без изоляции** | `./run.sh`, тесты, `app.cli validate/sync` |

Запуск в контейнере занимает ~0,25 с. Одновременно выполняется не больше `CODEQUEST_MAX_RUNS` (4)
программ, у каждого пользователя — не больше 30 запусков в минуту.

```bash
.venv/bin/python -m app.cli sandbox-check   # собрать образ песочницы и проверить изоляцию — перед открытием сервера
.venv/bin/pip install -e deploy/runner/pwfake   # локально: учебный Playwright для проверки UI-заданий в режиме local
```

Процессу сервера нужен доступ к Docker (`docker` в PATH). Доступ к Docker-демону равен root-доступу к хосту:
не запускай на этой машине ничего лишнего и не давай доступ к ней посторонним.

## Приложение на телефоне (PWA)

CodeQuest ставится на главный экран как приложение: манифест `/manifest.webmanifest`, иконки в `static/icons/`,
service worker `/sw.js` (кэширует оболочку, чтобы приложение открывалось без сети; ответы `/api` не кэшируются).

- **Android / Chrome:** меню ⋮ → «Установить приложение» (или кнопка в «Настройках»).
- **iPhone / Safari:** «Поделиться» → «На экран „Домой“». Установленное приложение хранит cookie отдельно
  от Safari — войти нужно один раз заново.

PWA работает только по **HTTPS** (исключение — `localhost`), так что на телефоне заработает после выкладки на домен с сертификатом.
Версия кэша — хеш файлов `static/`, после обновления сервера приложение подтягивает новую версию само.

## Перед выкладкой в интернет

Пошаговая выкладка на VPS с Ubuntu — [`deploy/README.md`](deploy/README.md) (скрипт `deploy/install.sh` делает всё ниже сам).


1. HTTPS-прокси (nginx/Caddy) перед `python -m app`, прокси передаёт `Host` и `X-Forwarded-For`.
2. `CODEQUEST_SECURE_COOKIE=1`.
3. `CODEQUEST_SANDBOX` не задан или `docker`; `app.cli sandbox-check` прошёл.
4. Первым зарегистрируйся сам — первый аккаунт становится администратором.

## Контент

Два равноправных способа, оба пишут в одни и те же таблицы:

1. **Админка** — раздел «Контент» в приложении.
2. **JSON-пакет** — например, сгенерированный Claude:
   ```bash
   .venv/bin/python -m app.cli validate content/my-topic.json   # проверить эталоны и вывод
   .venv/bin/python -m app.cli import   content/my-topic.json   # загрузить
   ```
   или через кнопку «Импорт JSON» в админке.

Пакеты из репозитория описаны на Python в `content/src/` (так удобнее писать код заданий).
Пересобрать, проверить и загрузить тему:

```bash
.venv/bin/python -m content.src.build py_classes          # content/src/py_classes.py → content/py-classes.json
.venv/bin/python -m app.cli validate content/py-classes.json
.venv/bin/python -m app.cli sync                           # загрузить все пакеты по content/ORDER, убрать удалённые темы
```

`sync` делает и `update.sh` на сервере. Перед ним полезно сохранить копию базы в `data/backups/`.

Каждый элемент имеет стабильный `slug`, прогресс привязан к нему — повторный импорт
обновляет задания, но не сбрасывает прогресс. Импорт никогда ничего не удаляет.

### Теория урока

- `theory` — краткая теория перед заданиями.
- `theory_full` — подробный урок (markdown). Блоки ```` ```python ```` получают кнопки «Запустить» и «Изменить»,
  а `validate` запускает каждый такой пример — пакет с упавшим примером не пройдёт проверку.
  Блоки ```` ```py ````, ```` ```yaml ````, ```` ```bash ```` только подсвечиваются.
- `quiz` — вопросы «Проверь себя»: `[{"q": "...", "options": ["...", "..."], "answer": 0, "explain": "..."}]`.

### Типы заданий

- `code` — ученик пишет код; проверяется функциями `test_*` из поля `tests`.
  В тестах доступны имена из кода ученика, `OUTPUT` (всё напечатанное) и `capture(f, *args)`.
  В темах про тестирование ученик пишет **свои тесты**: проверка запускает на них настоящий pytest
  (`pyt()` и `run_pytest()` в `content/src/_lib.py`) — на исправной системе и на подменённой «сломанной»
  (`patch=`), и тест засчитывается, только если ловит баг.
- `output` — ученик читает `code` и вводит, что он выведет (`expected_output`).
- `command` («Терминал») — ученик вводит команду одной строкой. В `expected_output` допустимые варианты
  по одному на строку, вариант `re:…` — регулярное выражение; лишние пробелы и `$ ` в начале не мешают.
  В `code` — необязательный контекст (например, вывод терминала), он не запускается.

## Резервная копия

`data/codequest.db` — это весь контент, все аккаунты и весь прогресс. Копируй его при остановленном
сервере или через `sqlite3 data/codequest.db ".backup backup.db"`.
